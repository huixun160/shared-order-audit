# H5：Tufts 的负荷解码器在解码负荷，还是在解码共用顺序？（2026-10-06）

脚本：`scripts/24_tufts_transfer.py`；结果：`results/tufts_transfer/summary.csv`、`per_subject.csv`。

## 设计

数据：68 名被试的原始测试段（区组 14–16，n = 0, 1, 2，顺序对所有人相同）。另做官方二分类（0 vs 2-back）。
窗口长度 4 s：
- **任务窗口**：每个区组取 8 个，结束于开始后 10, 20, …, 80 s；
- **休息末尾窗口**：每个区组取 1 个，结束于指导语出现的时刻。此时被试还没看到下一个区组的任何信息。

特征为 32 个通道的均值和斜率，分类器是标准化 + 逻辑回归（C = 0.1），留一被试。四种组合：

| 训练 → 测试 | 含义 |
|---|---|
| 任务 → 任务 | 常规解码器 |
| 任务 → 休息 | 任务解码器在休息期是否已经"预测出"下一个区组 |
| **休息 → 任务** | **从没见过任务的解码器**，在任务上能得多少分 |
| 休息 → 休息 | 开始前探针 |

## 结果（原始数据，不滤波）

| 基线 | 任务 | 任务→任务 | 任务→休息 | **休息→任务** | 休息→休息 |
|---|---|---|---|---|---|
| 整段均值（常规按被试归一化） | 3 类（机会 33.3%） | 47.1% | 46.1% | **46.5%** | 48.0% |
| 整段均值 | **0 vs 2（机会 50%）** | **70.3%** | 68.4% | **70.4%** | 70.6% |
| 因果长基线（只用窗口之前的数据） | 3 类 | 38.8% | 35.3%（不显著） | **37.4%**（p = 2e-4） | 39.2% |
| 因果长基线 | 0 vs 2 | 58.8% | 55.1%（p = 0.10） | **58.5%**（p = 3e-4） | 55.9% |

（除标注外 p < 0.001，单侧 Wilcoxon，被试为单位）

**要点**：
- 在原始数据和常规的按被试归一化下，**一个只在休息期（任务开始前、指导语出现前）训练、从没见过任务数据的解码器，在任务窗口上的准确率与任务解码器完全相同**（0 vs 2：70.4% 对 70.3%；3 类：46.5% 对 47.1%）。
- 反过来，任务解码器在休息期就能以 68.4% 的准确率"预测"下一个区组是 0-back 还是 2-back。
- 只用窗口之前的数据做基线，这个模式不变（58.5% 对 58.8%）。
- 作为对照：Tufts 论文报告的官方跨被试 0 vs 2 准确率约为 72%（30 s 窗口、官方滤波），和这里 70% 的量级相同。

## 加上高通滤波后（"官方式"零相位 0.001–0.2 Hz 三阶 Butterworth）

| 基线 | 任务 | 任务→任务 | 任务→休息 | 休息→任务 | 休息→休息 |
|---|---|---|---|---|---|
| 整段均值 | 0 vs 2 | 59.3%（p = 0.001） | 46.3% | 44.8% | 55.9%（p = 0.10） |
| 整段均值 | 3 类 | 39.7%（p = 0.001） | 30.9% | 31.2% | 38.7%（p = 0.09） |

- 高通之后交叉迁移消失，任务解码降到 59%（0 vs 2，4 s 窗口）。这说明零相位高通去掉了大部分顺序漂移；剩下的任务信号约为 +9 点。
- **重要局限**：这里的滤波只作用在约 600 s 的测试段上（官方是对整个约 40 min 的会话滤波）。0.001 Hz 的截止周期是 1000 s，比测试段还长，所以这里的高通**比官方强得多**，会把整段线性趋势都去掉。
  因此这一行**不能**代表官方预处理的实际效果。要复现官方效果，需要整段会话的原始数据，而这只有 9 人有。下一步改用官方发布的 `whole_data`（全部 68 人，16 个区组）在官方协议下检验。

## 解读（暂定）

1. 预处理决定了解码器学到的是"负荷"还是"顺序"：原始数据加常规归一化时，任务解码的分数完全可以由顺序信息得到；强高通会去掉大部分顺序漂移，同时任务分数也大幅下降。
2. 在共用顺序的设计下，**评估分数本身无法区分这两种情况**。这正是论文的核心论点。
3. 尚需在官方数据和官方协议下确认（下一步）。

## 官方数据、官方协议下的检验（`scripts/25_tufts_official.py`，`results/tufts_official/`）

数据：官方发布的 `band_pass_filtered/whole_data`。全部 68 人，每人 16 个任务段（每段 426 个样本，8 个 Hb 通道，零相位 0.001–0.2 Hz）。
已核对：68 人的顺序全部是 `0123123023013012`。该发布版本里没有休息段，所以这里不能做开始前探针，改做下面三项分析。

### 1. 复现基准
30 s 窗口（150 个样本，步长 15），官方逻辑回归特征（每通道均值、标准差、斜率、截距），留一被试，0 vs 2：
**64.2%**（全部区组，p = 2e-9）；**67.8%**（官方测试用的区组 9–16）。官方报告约 72%（调参后的模型）。

### 2. 区组内时间进程（5 s 窗口）
0–5 s 为 52.0%（p = 0.07），5–10 s 为 50.0%；从 15 s 起上升（56%），45–65 s 达到 62–65%。
**在官方数据里，区组开始阶段没有明显的可解码信息**，准确率随血流动力学响应上升。这一点如实记录：官方的处理方式没有在任务开头留下明显的"提前可解码"痕迹。

### 3. 分类器到底受什么影响（最重要）

把 0 vs 2 分类器（留一被试）应用到**全部 16 个区组**（包括 1-back 和 3-back），统计每个窗口被判为"0-back"的概率 P0，按区组取平均。
回归模型：P0 ~ 真实负荷 + 会话中的位置 + 上一个区组是否为 3-back + 被试固定效应，标准误按被试聚类。

| 因素 | 系数 | p |
|---|---|---|
| 真实负荷：2-back 对 0-back | −0.081 | 6e-6 |
| 真实负荷：3-back 对 0-back | −0.084 | 1e-6 |
| **会话位置（每个区组）** | **+0.0052（整个会话累计约 +0.078）** | **3e-6** |
| **上一个区组是 3-back** | **+0.044** | **7e-4** |
| （加入"是否第一个区组"后：上一个区组是 3-back） | +0.047 | 0.011 |
| 是否第一个区组 | +0.007 | 0.85（不显著） |

- 在真实负荷不变的情况下，P0 随会话位置单调上升（1-back 内 ρ = 0.40，p = 3e-9；0-back 内 ρ = 0.25，p = 0.001）。
- **整个会话中位置造成的偏移，和真实负荷的效应一样大；"上一个区组是 3-back"的效应约为负荷效应的一半多。**
- 在 Tufts 的固定顺序下，除第一个以外的 0-back 全部前接 3-back，所以这条残留恰好把分类器推向正确答案。
  直接证据：第 1 个 0-back（唯一没有前接 3-back 的那个）准确率只有 **44.9%**，后面三个 0-back 平均 **64.9%**（配对 Wilcoxon p = 0.0006）。
  加入位置项后，"第一个区组"本身不显著，差异主要由"上一个区组是 3-back"解释。

### 4. 反事实估计：去掉 3-back 残留之后的基准分数
在 P0 上扣除 0.044–0.047 的"前接 3-back"偏移后重新判别：

| | 原始 | 扣除残留后 |
|---|---|---|
| 全部区组 | 64.2% | 60.7–61.0% |
| 官方测试区组（9–16） | 67.8% | 63.7–64.0% |

也就是说，超出机会水平的那部分（17.8 点）里，**约 4 点（约 23%）可以归因于"前一个区组是 3-back"这一条顺序残留**。
局限：这是基于线性概率偏移的粗略估计，系数和准确率来自同一份数据；会话位置效应在 0 vs 2 中大致平衡（两类的平均位置相同），因此没有计入虚高，但它会增加噪声，使部分区组被系统性误判。

## 汇总（H5）

1. 原始数据加常规按被试归一化：**从没见过任务的"休息期解码器"与任务解码器分数相同**（0 vs 2：70.4% 对 70.3%）。
2. 官方数据、官方协议：基准分类器的输出**系统性地受会话位置和前一区组负荷影响**，影响量级与真实负荷相当；按保守估计，约四分之一的超机会准确率来自顺序残留。
3. 评估协议（留一被试）无法发现这些问题，因为所有被试共用同一个顺序。
